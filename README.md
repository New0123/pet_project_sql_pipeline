# 🛠️ SQL Pipeline Runner (Pet Project)

**Легковесный аналог ETL-оркестратора для редких (ad-hoc) задач.**

Этот проект создан как альтернатива полноценным пайплайн-инструментам (таким как Apache Airflow, Dagster или Prefect) для тех случаев, когда:
- Развертывание и поддержка тяжелого оркестратора избыточны или невозможны (например, из-за ограничений инфраструктуры или безопасности).
- Нужно быстро прогнать последовательность SQL-скриптов без настройки DAG-ов и веб-интерфейсов.
- Требуется простое, надежное и прозрачное решение на чистом Python.

Изначально скрипт создавался для последовательного запуска DDL/DML операций в **Greenplum/PostgreSQL**, но подойдет для любой СУБД, для которой есть драйвер `psycopg2`.

## 💡 Зачем это нужно?

В ситуациях, когда нет CI/CD для баз данных или доступа к полноценной платформе оркестрации, инженеру часто приходится выполнять скрипты вручную. Этот инструмент автоматизирует этот процесс: он сам найдет файлы в правильном порядке, подставит нужные параметры, выполнит их и напишет подробный отчет.

### Ключевые особенности:
- **Умная сортировка файлов:** Скрипты выполняются в естественном порядке (`1.sql`, `2.sql`, ..., `10.sql`), а не по алфавиту (`1.sql`, `10.sql`, `2.sql`).
- **Гибкая система параметров:** Поддержка безопасной подстановки (`:param` -> `'value'`) и «сырой» подстановки для имен таблиц/партиций (`~param~`).
- **Защита секретов:** Чтение `.env.secret` с поддержкой секций. Пароли никогда не попадают в логи.
- **Отказоустойчивость:** При первой же ошибке процесс останавливается, а транзакция откатывается. 
- **Подробное логирование:** Каждый шаг фиксируется в консоли и в файле `resume_exec.txt` (количество затронутых строк, время выполнения, статус).
- **Безопасность:** Поддержка `gssencmode` и `sslmode` для специфичных сборок Greenplum/Postgres.

## 🚀 Быстрый старт

1. Установите зависимости:
```bash
python3 -m pip install psycopg2-binary
```

2. Создайте файл `.env.secret` в корне проекта (или рядом со скриптом) с доступами к БД:
```env
GP_HOST=gp.example.local
GP_PORT=5432
GP_DB=dwh
GP_USER=user
GP_PASSWORD=secret
```

3. Создайте файл `param.txt` рядом со скриптом:
```text
:prd = '2025-08-01'
:mm_id = 10
```

4. Положите ваши SQL-файлы в папку со скриптом (`1.sql`, `2.sql` и т.д.) и запустите:
```bash
python3 run_sql_pipeline.py
```

## ⚙️ Подстановка параметров в SQL

Скрипт поддерживает два вида плейсхолдеров:

**1. Безопасная подстановка `:name`**
Значение экранируется и оборачивается в кавычки (если это не число).
```sql
SELECT * FROM orders WHERE dt = :prd;
-- Превратится в: SELECT * FROM orders WHERE dt = '2025-08-01';
```

**2. «Сырая» подстановка `~p_name~`**
Используется для подстановки имен таблиц, партиций, списков или форматов дат. Кавычки не добавляются, ведущие нули сохраняются.
```sql
SELECT * FROM schm.tab_name_p~p_mm_id~;
-- Превратится в: SELECT * FROM schm.tab_name_p10;

SELECT to_date('~p_strt_dt~', '~p_dt_fmt~');
-- Превратится в: SELECT to_date('20260101', 'YYYYMMDD');
```

## 🛠️ Полезные команды (CLI)

- `--dry-run` — посмотреть план выполнения и проверить, все ли параметры заданы, без подключения к БД.
- `--check-connection` — проверить доступность базы данных и вывести версию сервера.
- `--param name=value` — передать или переопределить параметр прямо из командной строки.
- `--truncate-log` — очистить файл `resume_exec.txt` перед запуском (по умолчанию лог дописывается).
- `-v` — выводить каждый выполненный оператор в консоль.

## 📄 Статус проекта и ограничения

Это **pet-проект**, созданный для решения конкретной локальной боли. Он не претендует на замену Airflow в production-среде.
